# new-chapter

새 챕터를 표준 구조로 만든다.

## 입력

`<번호> <제목>` 형식의 args. 예:
- `03 백엔드 기초`
- `06 보안과 컴플라이언스`

번호는 두 자리(`01`, `02`, ...)로 정규화한다. 제목에 공백이 포함될 수 있다.

## 절차

1. **중복 확인**: `manuscript/` 아래에 같은 번호로 시작하는 디렉토리가 이미 있으면 사용자에게 확인 후 진행. 덮어쓰지 말 것.
2. **디렉토리 명명**: `manuscript/<번호>-<제목-슬러그>/`
   - 슬러그: 한글은 그대로 두고 공백을 `-` 로 치환. 영문 약어는 소문자로.
   - 예: `06 보안과 컴플라이언스` → `manuscript/06-보안과-컴플라이언스/`
3. **README.md 생성**: 아래 템플릿을 그대로 사용. 제목과 번호만 치환하고 본문은 placeholder 로 남긴다.
4. **결과 보고**: 생성된 파일 경로를 `file_path:line` 형식으로 알려주고, 사용자에게 다음으로 채워야 할 곳 ("이 장에서 답하는 질문" 3~5개) 을 안내.

## README.md 템플릿

```markdown

- (질문 2)
- (질문 3)

(왜 이 주제가 아키텍트에게 중요한지. 국내 환경에서의 맥락. 5~10줄.)

## 1. (첫 번째 절 제목)

(본문)

(이 장에서 다룬 내용을 케이스 스터디 서비스에 어떻게 적용하는지. 1~2 페이지.)

## 정리 — 체크리스트
```

## 주의

- 본문을 미리 채우지 말 것. 사용자가 이어서 작성한다.
- `이 장에서 답하는 질문`, `트레이드오프`, `체크리스트` 세 섹션은 절대 삭제하지 말 것 — 책 전체의 일관성 기준이다.
- 챕터의 코드 예제가 필요해질 경우 `code-samples/<번호>-<주제>/` 가 짝이 된다는 점만 안내하고, 디렉토리는 미리 만들지 말 것 (예제가 실제로 필요할 때 생성).
