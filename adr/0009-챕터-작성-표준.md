# 0009. 챕터 작성 표준 — 절별 박스 / 다이어그램 / 약어 / 인용 형식

- **Date**: 2026-05-08
- **Status**: Accepted
- **Deciders**: 저자

## Context

book-editor 일괄 검토 (1장 + 02~08 챕터, 2026-05-08) 에서 4가지 P2 패턴이 7개 챕터에 일관되게 확산되어 있음을 확인.

1. 절별 트레이드오프/체크리스트 박스 누락 (전 챕터)
2. 기술 약어 첫 등장 시 풀이 누락 (전 챕터)
3. 핵심 결정 절에 다이어그램 부재 — 4장·6장은 Mermaid 0개
4. 더 읽을거리 인용 형식 일관성·URL 부재

CLAUDE.md "원고를 쓸 때" 가이드는 박스 룰만 한 줄 명시. 나머지 3 패턴은 명문화되지 않아 챕터마다 자의적으로 누락됐다.

## Decision

다음 4가지 표준을 모든 챕터(00~08 + 케이스 스터디) 에 강제한다.

### 룰 1 — 절별 박스

- 모든 1차 절(`## N. ...`) 끝에 다음 중 **하나 이상** 이 있어야 한다.
  - **트레이드오프** — 표 형태, 옵션 비교 (행: 측면, 열: 옵션)
  - **체크리스트** — GFM 체크박스 (`- [ ]`)
  - **함정 / 흔한 실수** — 인용 `>` 또는 bullet 나열
- 면제: 도입성 절(예: "역할 정의", "용어 풀이") 만. 면제 시 본문에 "이 절은 도입이라 박스 없음" 표기 또는 다른 절로 통합.

### 룰 2 — 약어 / 외래어 표기

- 모든 기술 약어·외래어는 **챕터 내 첫 등장 위치** 에서 다음 중 하나로 풀이.
  - "한국어 풀이(영어)" — 예: "관측성(Observability)"
  - "한국어 풀이(영어 약어)" — 예: "정보보호 관리체계(ISMS)"
  - "약어 (영어 풀이)" — 예: "RLS (Row-Level Security)"
- "이 장에서 답하는 질문" 안에 등장하는 약어도 풀이 필요.
- **면제**: 도구 / 제품 고유명 (Helm, ArgoCD, Spring Boot, Kafka 등). 단 약어형 도구명 (`MSK`, `EKS` 등) 은 첫 등장 시 풀어 표기 권장.

### 룰 3 — 다이어그램

- 한 챕터 당 Mermaid 다이어그램 **최소 2개 이상**.
- 다음 영역의 절에는 다이어그램이 있어야 함.
  - 시스템 구조 (C4 Context / Container)
  - 데이터 플로우
  - 시퀀스 (분산 흐름·실패 경로)
  - 케이스 적용 절의 핵심 결정
- 추상 개념만 다루는 도입 챕터(00 들어가며) 는 면제.

### 룰 4 — 더 읽을거리 인용 형식

한 챕터 안에서 형식 일관 적용. 형식:

- **책**: `*제목*, N판 — 저자명 (출판사, 연도) — 한 줄 요약`
- **공식 문서 / 가이드라인**: `이름 — 발행처 (URL — 확인된 것만)`
  - URL 미확인 시 URL 칸 자체 비우고 "URL 확인 필요" 표시.
- **법규 / 표준**: `「법령명」 (관련 조문 또는 발행 연도) — 발행처 (확인 필요)`
- **온라인 글 / 블로그**: `제목 — 저자, 발행처 (연도) (URL — 확인된 것만)`

## Considered Alternatives

- **명문화 안 함**: 7개 챕터가 자의적으로 적용 — 현 상태가 그것. 거부.
- **CLAUDE.md 에만 추가**: 가이드 한 줄로는 잊힘. ADR 로 분리해야 변경 추적 가능.
- **더 강한 룰** (예: 모든 절마다 다이어그램 의무): 글의 흐름 깰 위험. 거부.

## Consequences

### 긍정적
- 책 전체 형식 일관성 확보
- book-editor 가 룰 기반으로 자동 점검 가능
- 외부 리뷰어가 "왜 이 챕터만 다른가" 묻지 않음

### 부정적
- 기존 7개 챕터의 P2 일괄 수정 작업 발생 (1회 비용)
- 모든 절에 박스 강제 → 일부 절은 박스가 형식적이 될 위험 (book-editor 가 "형식적 박스" 도 P3 로 잡도록 보완)
