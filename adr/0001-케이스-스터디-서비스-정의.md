# 0001. 케이스 스터디 서비스 정의 — 원픽(OnePick)

- **Date**: 2026-05-08
- **Status**: Accepted
- **Deciders**: 저자

## Context

이 책은 8개 영역(아키텍처/클라우드/백엔드/프론트엔드/데이터/보안/운영/종합)을 다룬다.
각 영역마다 따로 예제를 만들면 책의 통일감이 떨어지고, 독자도 매번 새 도메인을 학습해야 해서 본질에 집중하기 어렵다.

## Decision

책 전체를 관통할 가상의 케이스 서비스를 **"원픽(OnePick)"** 이라는 월 1,000만 MAU 종합 커머스로 정의한다.
직매입 30% / 입점 60% / 라이브 10% 의 매출 비중을 가지며, 한국 시장에 한정된 B2C 모델이다.

상세 정의는 `manuscript/case-study/README.md` 에 둔다.

## Considered Alternatives

- **핀테크 / 간편결제**: 보안·전금법을 깊게 다룰 수 있으나 진입 난이도가 높아 일반 독자에게 부담.
- **B2B SaaS**: 멀티테넌시·SSO 등 모던한 패턴을 보여주기 좋으나 국내 특수성(망분리·간편로그인)이 약함.
- **공공/금융 시스템**: 망분리·KISA 가이드를 가장 깊게 다룰 수 있으나 일반 독자 거리감.

→ 커머스가 8개 영역 모두에서 자연스러운 예제를 제공하면서, 결제·본인인증을 통해 국내 특수성도 충분히 다룰 수 있다고 판단.

## Consequences

### 긍정적
- 모든 챕터가 동일한 도메인을 참조 → 독자의 인지 부하 감소
- 결제·물류·정산 등 도메인 풍부함 → 트레이드오프 사례가 다양
- 국내 PG·간편로그인·본인인증을 자연스럽게 다룰 수 있음

### 부정적
- 핀테크/공공 영역의 깊은 보안 사례를 보여주지 못함 → 별도 박스로 보완
- 커머스에 익숙하지 않은 독자(예: 게임/미디어 산업)는 일부 사례가 낯설 수 있음

### 중립
- 케이스를 변경하면 거의 모든 챕터를 다시 써야 함 → 변경은 신중히
