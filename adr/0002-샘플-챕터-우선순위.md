# 0002. 샘플 챕터로 1장 "아키텍처 기초" 우선 작성

- **Date**: 2026-05-08
- **Status**: Accepted
- **Deciders**: 저자

## Context

8개 영역을 동시에 시작하면 형식·톤·난이도가 어긋난다.
한 챕터를 끝까지 완성해 책 전체의 템플릿을 확정해야 한다.

## Decision

**1장 "아키텍처 기초"** 를 첫 샘플 챕터로 한다.
이 챕터로 표준 챕터 구조의 실용성, 트레이드오프 박스의 형식, 케이스 스터디 적용 절의 적정 분량을 확정한다.

## Considered Alternatives

- **2장 클라우드/인프라**: 국내 차별점이 가장 두드러지나 실제 콘솔 캡처·예제 검증 부담.
- **3장 백엔드**: 코드 예제로 빠르게 검증 가능하나 추상도가 낮아 책 전체 톤을 잡기 어려움.
- **6장 보안/컴플라이언스**: 차별점 가장 강하나 법규 시점 관리·집필 난이도가 가장 높음.

→ 1장은 가장 추상적이라 책의 톤을 잡기 좋고, 외부 피드백도 도메인 무관하게 받기 쉬움.

## Consequences

### 긍정적
- 책 전체의 형식이 1장에서 확정됨 → 이후 7개 챕터 일관성 확보
- 외부 베타 리뷰를 일찍 받을 수 있음

### 부정적
- 추상적 내용이라 독자가 흥미를 잃을 위험 → 케이스 적용 절을 충분히 둠
