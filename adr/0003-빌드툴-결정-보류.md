# 0003. 빌드/출판 도구 결정 보류 — 마크다운 우선

- **Date**: 2026-05-08
- **Status**: Accepted
- **Deciders**: 저자

## Decision

빌드/출판 도구(mdBook · Quarto · Next.js 기반 사이트 · 출판사 등)의 선택은 **Phase 3 (영역별 1차 드래프트) 중반까지 보류** 한다.
당분간은 GitHub 에서 마크다운 그대로 읽힐 수 있는 형태로만 작성한다.

## Context

빌드툴별로 지원하는 마크다운 확장(인용·콜아웃·수식·다이어그램 임베딩 등)이 다르다.
지금 결정하면 글의 표현이 도구에 종속되고, 도구 전환 시 다시 수정해야 한다.
반대로 너무 늦게 결정하면 빌드 단계에서 발견되는 문제(이미지 경로·크로스 레퍼런스)를 한꺼번에 처리해야 한다.

## Considered Alternatives

- **mdBook 즉시 채택**: 가장 단순. 단 Mermaid 외 인터랙티브 요소 약함.
- **Quarto 즉시 채택**: 코드 실행·표·그림 강함. 단 의존성 무겁고 한글 PDF 빌드 검증 필요.
- **Next.js + MDX**: 자유도 최대. 단 책 작성 외 프론트 코드 유지보수 추가됨.

## Consequences

### 긍정적
- 콘텐츠에 집중. 도구 결정에 시간 낭비 안 함.
- 마크다운 표준 문법만 쓰면 어떤 도구로도 마이그레이션 가능.

### 부정적
- 후반에 빌드 도입 시 이미지 경로·코드 블록 메타·각주 형식 등을 일괄 수정해야 함.
- 인터랙티브 요소(접기/탭/실시간 미리보기)를 본문에 못 씀.

## 작성 규칙 (도구 종속을 피하기 위해)

- **표준 마크다운만 사용**. GFM 표·코드펜스·인용·체크박스까지만 OK.
- **Mermaid** 는 코드 블록 ` ```mermaid ` 로 작성 (대부분 도구가 지원).
- **이미지 경로**는 `assets/` 아래 상대 경로.
- **각주**는 `[^n]` 형식.
- **HTML 태그 사용 금지** (콜아웃은 인용 `>` + bold 로 대체).
