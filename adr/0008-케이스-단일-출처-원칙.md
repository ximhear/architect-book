# 0008. 케이스 스터디는 단일 출처 (Single Source of Truth)

- **Date**: 2026-05-08
- **Status**: Accepted
- **Deciders**: 저자

## Context

1장 "아키텍처 기초" 의 book-editor 1차 검토 (2026-05-08) 에서 다음 패턴이 발견됐다.

- 1장 7.1 "현 상황" 절이 `case-study/README.md` 에 없는 원픽 관련 수치를 본문에서 자체 생산
  - "엔지니어 60명에서 220명으로 성장"
  - "배포가 1일 평균 1회"
  - "결제 도메인의 트랜잭션 락이 주문 흐름 전체를 가끔 멈춤"
  - "검색 / 추천이 메인 DB 의 부하의 50% 차지"

이 패턴이 굳으면 7개 챕터가 각자 조금씩 다른 원픽을 묘사하게 된다.
같은 책 안에서 케이스가 갈라지면 일관성·신뢰감 모두 무너진다.

## Decision

`manuscript/case-study/README.md` 를 원픽에 대한 **단일 출처(Single Source of Truth)** 로 정한다.

**규칙**

1. 챕터 본문에서 원픽의 조직·트래픽·데이터·문제 상황을 인용할 때는 케이스 스터디 README 에서 가져온다.
2. 챕터에서 새로운 케이스 수치/사실/상태가 필요하면, **먼저 케이스 스터디 README 를 갱신** 한 뒤 챕터에서 인용한다.
3. 가설·사고실험을 위한 임시 가정이라면 본문에 명시한다 — "이 절의 논의를 위해 X 를 가정한다" 형태.
4. 케이스 스터디 README 의 변경은 [변경 이력] 절에 기록한다.

## Considered Alternatives

- **챕터별 자체 가정 허용**: 일관성 보장 안 됨. 7개 챕터가 갈라짐. 책의 신뢰성 손상.
- **케이스 동결, 추가 수치 금지**: 케이스가 풍부해지지 못함. 챕터 깊이 제약. 사실상 비현실적.

## Consequences

### 긍정적
- 책 전체에 걸쳐 원픽이 한 모습으로 유지됨
- 케이스 갱신 시 한 곳만 보면 영향 추적 가능
- 외부 리뷰어·번역자에게도 단일 참조점 제공

### 부정적
- 챕터 작성 시 케이스 스터디 갱신이 추가 단계로 들어감 (작은 비용)

### 중립
- book-editor 점검 항목이 1개 늘어남
