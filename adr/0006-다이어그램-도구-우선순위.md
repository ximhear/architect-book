# 0006. 다이어그램 도구 우선순위 — Mermaid 우선

- **Date**: 2026-05-08
- **Status**: Accepted
- **Deciders**: 저자

## Decision

다이어그램은 다음 우선순위로 작성한다.

1. **Mermaid** — 시퀀스, 플로우차트, 클래스, ER, C4(`C4Context`/`C4Container` 등)
2. **Excalidraw** — Mermaid 로 표현이 부자연스러운 자유 도형 (아키텍처 개념도, 메타포)
3. **drawio** — 위 둘로 안 되는 복잡한 시스템 구조도

원본은 `diagrams/<chapter>/` 에, 렌더된 이미지는 `assets/<chapter>/` 에 둔다.
Mermaid 는 본문 코드블록으로 삽입 (별도 파일 분리하지 않음).

## Context

빌드툴 결정을 보류했으므로(ADR-0003) 어떤 도구로 빌드해도 보존되는 형식이 필요하다.
Mermaid 는 GitHub·mdBook·Quarto·Next.js MDX 모두에서 지원된다.
Excalidraw 는 PNG + .excalidraw (편집 가능) 두 형태를 함께 보관한다.

## Considered Alternatives

- **drawio 우선**: 표현력 최대. 단 GitHub 미리보기에서 확인 불편.
- **PlantUML**: 강력하나 Java 의존성·렌더 환경 필요.
- **이미지(PNG)만**: 가장 단순하나 수정 시 원본 분실 위험.

## Consequences

### 긍정적
- 텍스트 기반 다이어그램이라 diff 추적 가능
- 빌드툴 변경 시에도 거의 그대로 유지

### 부정적
- 복잡한 다이어그램은 Mermaid 로 표현이 어색할 수 있음 → Excalidraw 로 fallback
