# 케이스 스터디 — 동네에너지 (MaeulEnergy)

> 본 책 (2권) 전체를 관통하는 가상의 세종 스마트시티 시민 참여형 에너지 플랫폼.
> 모든 장의 예제·다이어그램·트레이드오프는 이 서비스를 기준으로 한다.
>
> 실존하는 어떤 사업과도 무관하다. 단 세종 스마트시티 5-1 생활권의 공개 자료를 토대로 합성했다.
>
> [ADR-0008](../../adr/0008-케이스-단일-출처-원칙.md) 단일 출처 원칙 — 새 사실은 이 문서를 먼저 갱신 후 챕터에서 인용.

## 한 문장 정의

**동네에너지(MaeulEnergy)** 는 세종 스마트시티 5-1 생활권을 무대로, **시민 참여형 통합 에너지 플랫폼** 을 운영한다.
가정 IoT 모니터링 + 수요반응(DR, Demand Response) 보상 + P2P 잉여 전력 거래 + 에너지 컨설팅·시공사 매칭 + 취약계층 에너지 복지 — 5개 축을 한 시민 앱에 묶었다.
세종시 스마트시티 사업의 일부로 시작 (시민 5만 가구 활성). 운영 3년차, 공공 위탁 + 시리즈 A 마친 비영리 + 영리 혼합 조직.

## 1. 비즈니스 / 도메인

### 1.1 5개 축 (대인 영역 강조)

| 축 | 설명 | 대인 / 공공 요소 | 매출 모델 |
|----|------|---------------|----------|
| 1. **IoT 모니터링** | 가정 스마트미터·태양광·EV·웨어러블 데이터 수집 + 시각화 | 사용자 본인 | 무료 (플랫폼 게이트웨이) |
| 2. **수요반응 (DR) 참여** | 피크 시 시민이 절약 → 한전 / KPX (한국전력거래소) 보상 → 시민에 지역화폐(세종페이) 환급 | 시민 ↔ 한전 | DR 보상의 10~15% 수수료 |
| 3. **P2P 잉여 전력 거래** | 가정 태양광 잉여 → 이웃에 판매 (분산에너지 특별법 시범사업) | 시민 ↔ 시민 | 거래 수수료 3% |
| 4. **컨설팅·시공사 매칭** ★ | 에너지 진단사·단열·보일러·태양광 시공사를 시민에 매칭 | 시민 ↔ 진단사 ↔ 시공사 (**핵심 대인 영역**) | 매칭 / 시공 수수료 |
| 5. **취약계층 에너지 복지** | 에너지 빈곤 가정 자동 식별 + 복지부·지자체 연계 | 시민 ↔ 공공 ↔ 사회복지사 | 공공 위탁비 |

### 1.2 비즈니스 KPI (가정)

- **활성 가구**: 5만 (세종시 전체 가구의 약 30%)
- **연 거래액 (P2P + 컨설팅·시공)**: 약 80억 원
- **DR 보상 환급액**: 연 약 12억 원 (시민 ↔ 한전 중개)
- **공공 위탁 + sponsor 수입**: 연 약 15억 원 (취약계층 연계 + 데이터허브 활용료)
- **운영 매출 합계**: 연 약 30~40억 원 (소규모 스타트업 + 비영리 혼합)

## 4. 팀 구조 (작은 조직, 1권과의 극명한 차이)

전체 26명 (엔지니어링 18명 + 사업·운영 8명) — 1권 220명 대비 약 1/8.

| 팀 | 인원 | 역할 |
|----|------|------|
| **인프라 / 플랫폼** | 4 | 클라우드·DevOps·관측성·IoT ingest 운영 (3 → 4 — IC 풀 1.67 FTE 부족 해소, 베타 반영) |
| **백엔드 (도메인)** | 6 | DR·P2P 거래·매칭·복지 연계 통합 (도메인팀 분리 X) |
| **데이터 / AI** | 3 | 시계열·DR 예측·취약계층 식별 모델 |
| **프론트엔드** | 3 | 시민 앱 (iOS / Android) + 콘솔 |
| **보안 / 컴플라이언스** | 1 (외부 자문 +) | 전기·에너지 법규 + 개인정보 + 공공 인증 (CSAP/PIA) |
| **사업 / 공공 협력** | 5 | 세종시·한전·복지부·시민 커뮤니티 |
| **운영 / CS** | 3 | 시민 응대 + 진단사 / 시공사 관리 |

> 인프라 4명 결정 배경 — IoT ingest 24/7 운영 + 야간 IC 풀 + 보안·관측성 + IaC 까지 3명으로는 1.67 FTE 부족으로 1년 운영 후 판단 (베타 검토 반영). 그래도 한 사람이 여러 영역 — 백엔드 6명이 7개 도메인 (DR/P2P/매칭/복지/IoT/회원/정산) 을 다 다룸.

## 5. 제약 / 컴플라이언스

### 5.1 법규 (대한민국 — 본 케이스 특수 영역)

> ⚠️ 본 케이스는 2026년 상반기 기준. 에너지 법규는 분기 단위로 변동 — 실 적용 시 최신 조문 확인.

- **전기사업법** — 전력 판매·중개·자가발전 등. 일반인 간 전력 직거래는 원칙 금지.
- **분산에너지 활성화 특별법** (2024.6.14 시행, 법률 제19470호) — 분산에너지 특화지역·소규모전력중개사업·통합발전소(VPP) 3 경로로 시민 참여 합법화. **본 케이스 P2P 는 「소규모전력중개사업」 경로 시범사업 등록을 가정**.
- **신·재생에너지 개발·이용·보급 촉진법** — 태양광 설치·보조금 (KEC 인증)
- **전력시장운영규칙** (KPX) — DR (수요반응자원) 시장 운영 / 보상 / SLA 근거. (「에너지이용합리화법」 은 절약 일반 정책의 근거이며, DR 시장 자체는 KPX 운영규칙)
- **개인정보보호법** — 전기 사용량은 **준 민감정보** (생활 패턴 / 가족 구성 / 부재 추론 가능)
- **전자금융거래법** — DR 보상 환급 + P2P 정산 (소액이라도 적용 검토)
- **사회복지사업법** + **사회보장급여법** — 취약계층 데이터 처리 + 정보 공유 동의
- **장애인차별금지법** + **지능정보화 기본법 제46조** — 공공 성격 앱 접근성 (KWCAG 2.2 AA 준수 의무)

### 5.1.1 공공 인증 (정부·세종시 위탁 요건)

- **CSAP** (Cloud Security Assurance Program) — 공공 위탁 클라우드 사업 필수. NCP 는 일반/표준 등급 보유 사실 확인 후 채택.
- **KCMVP** (Korean Cryptographic Module Validation Program) — 행정·공공 정보 암호화 모듈 검증. 시민 식별번호·복지 데이터 저장 / 통신 암호화 모듈은 KCMVP 인증 라이브러리 사용 의무.
- **PIA** (Privacy Impact Assessment, 개인정보 영향평가) — 공공기관 수탁 시 시행 의무. 매년 갱신 + 신규 도메인 추가 (예: 웨어러블) 시 재평가.
- **ISMS-P** — 민간 사업 영역은 권고, 공공 위탁 영역은 사실상 필수.

### 5.2 비즈니스 제약

- **DR 호출 응답 SLA**: 한전 / KPX 가 정한 응답 시간 내 정확한 절전량 보고 (분 단위 정확도)
- **취약계층 안전 SLA**: 혹한 / 혹서 시 웨어러블 알람을 5분 이내 사회복지사에게 전달 (도달률 분해: FCM 95~97% / SMS 98~99% / 자동전화 80~90% — 3채널 OR 합성 시 약 99.98%)
- **P2P 거래 정합성**: 잉여 전력 측정·정산 오차 0건 목표 (한전과의 정산 정합)
- **공공 신뢰**: 단 1건의 데이터 사고도 사업 중단 위험 (공공 위탁 계약 조건)

### 5.3 기술 제약

- **IoT 데이터 손실률**: 0.1% 이하 (DR 보상 / P2P 정산의 정확성)
- **시민 앱 응답**: p95 < 500ms (피크 시), 첫 화면 < 250KB
- **공공 API 호출 한도**: 한전 / KPX / 세종시 데이터허브 각각 일일 호출 한도 — 캐싱·배치 필수
- **데이터 보존**: 시민 전기 사용량 5년 (개보법 시행령) + DR 보상 정산 기록 영구

## 8. 인프라 / 클라우드 정책

> 정책 수준만 명시. 구체 채택은 [11. 기술 스택 상세](#11-기술-스택-상세-가정).

- **NCP 단일 클라우드** — 공공 데이터 연계·정부 사업 가점·시민 데이터 주권. 보조 클라우드 없음 (외부 SaaS 만 클라우드 외부).
- **온프레미스 옵션** — 한전 / 세종시 데이터허브 연동에 일부 폐쇄망 가능성
- **데이터 주권** — 모든 시민 데이터는 NCP 한국 리전. 분석 / AI 학습도 한국 리전 (HyperCLOVA X).
- **장애 격리** — 취약계층 안전 알람 경로는 다중화 (앱 푸시 실패 시 SMS, SMS 실패 시 전화 자동 — 모두 NCP SENS 경유)
- **단일 클라우드 락인 인지** — 멀티클라우드 운영 부담을 26명 조직이 못 짊어진다는 명시적 결정. 락인 회피는 IaC (Terraform) + 도구 추상화 (OpenTelemetry / Helm) 로 부분 완화. NCP 매니지드 격차 (Cloud Insight trace UX, ClickHouse 매니지드 없음 등) 는 [11.1 인프라](#111-인프라-ncp-단일-클라우드) 비고에 명시.

### 10.1 구체 신호 (수치 기준)

- **조직**: 26명 (엔지니어 18 + 사업 운영 8). 1권 220명의 약 1/8.
- **IoT 입력**: 일 2,700만 record / 월 8억 / 연 100억+. Kafka 호환 (NCP CDSS) **partition 32+ 권장** — 피크 ingest 분당 약 18,000 record 안정 처리.
- **시민 앱 RPS**: 평균 300 / 피크 3,000 (혹한·혹서·정책 발표 직후 약 10배 스파이크).
- **DR 호출 폭주**: 호출 빈도 **월 5~10회**. 한 호출 당 **첫 1분 5,000 TPS → 5분 1,000 → 30분 100 으로 감쇠**. 평소는 거의 0.
- **DR 응답 예측 단위**: **동·면 집계 (행정구역 단위, 50~500 가구)** 가 기본. 가구별 예측은 보조 신호로만 사용. Prophet **동·면 MAPE 8~12% 목표**, 가구별 MAPE 25~40% (참고용). 가구별 예측은 분산이 커서 보상 정산에는 직접 쓰지 않음.
- **취약계층 안전**: 혹한·혹서 시 일 평균 30건 알람 / 5분 이내 사회복지사 도달률 99.9% 목표. **3채널 OR 합성** → 1 − (1 − 0.95)·(1 − 0.98)·(1 − 0.80) ≈ 99.98% (FCM / SMS / 자동전화 각 단독 도달률 합성).
- **공공 API 호출**: 한전 AMI 일 호출 한도 X (협의 가정), KPX 호출 분당 60건 한도 (가정)
- **시민 신뢰 사고**: 단 1건 데이터 유출 = 공공 위탁 중단 — 사실상 회사 위기
- **P2P 거래 정합 오차**: 한전 측 정산과 0.01% 이내 — 분기 1회 reconciliation
- **NCP 매니지드 격차** (운영 시간 가산 사유): Cloud Insight trace UX 가 신생 (Tempo 대비 검색 UX 미흡), ClickHouse NCP 매니지드 없음 (NKS 위 self-host), Confluent Cloud 류 Kafka 외부 매니지드 없음 (CDSS 단일 선택).

| 한국어 특화 | HyperCLOVA X 도입 (Q3, ZRR 계약 체결 후) |

### 11.5 운영

- SRE 별도 X — 인프라 / 플랫폼 4명이 SRE 역할 겸함
- 도메인팀 = 백엔드팀 (분리 안 됨) 1차 온콜
- IC 풀: 인프라 4명 + 백엔드 시니어 2명 = 총 6명. 야간 / 주말 로테이션
- 회고: 모든 P1 인시던트 5일 이내, 비난 없는 회고
- 비용: **분기 1회 리뷰** (월간 X — 작은 조직 부담 최소화). IT 비용 매출 18~25% (공공 sponsor 일부 충당)
- **공공 신뢰 모니터링**: 별도 KPI — 시민 신뢰 점수 (분기 설문) + 사고 빈도
