# 6장. 보안과 컴플라이언스 — 에너지 / 공공 / 준 민감정보

> 1권의 ISMS-P + 전금법 + 개보법 위에, 에너지 법규와 공공 위탁 책임이 더해진다.

## 이 장에서 답하는 질문

- 「분산에너지 활성화 특별법」 의 P2P 거래 시범사업 조건은?
- 전기 사용량은 왜 "준 민감정보" 인가?
- 공공 위탁 계약의 보안 책임은 1권 PG 위탁과 어떻게 다른가?
- 25명 조직에 보안 1명 + 외부 자문 — 가능한가?

> ⚠️ **법규 인용 시점 면책**: 본 장 모든 법규는 **2026년 상반기 기준**. 에너지 법규는 분기 단위로 변동 — 실 적용 시 최신 조문 확인.

## 1. 한국 법규 — 동네에너지 특화

| 법령 | 핵심 | 1권 (커머스) 대비 |
|------|------|------------------|
| **개인정보보호법** | 전기 사용량 처리 — **준 민감정보 가능성** | 1권과 공통 + 준민감 해석 |
| **정보통신망법** | 시민 알림 / DR 푸시 | 1권과 공통 |
| **전기사업법** | 전력 판매 / 중개 | **신규** |
| **분산에너지 활성화 특별법** (2024) | 시민 참여 P2P 거래 합법 근거 | **신규 / 핵심** |
| **신·재생에너지법** | 태양광 / 보조금 | **신규** |
| **에너지이용합리화법** | DR 사업 근거 | **신규** |
| **사회복지사업법** | 취약계층 데이터 처리 | **신규** |
| **공공기관운영법 / 공공계약법** | 공공 위탁 일반 | **신규** |

### 1.1 전기 사용량 = 준 민감정보

법적 명시는 없지만 추론 가능성으로 **사실상 준 민감정보 취급**:
- 시간대별 전력 → 거주 / 부재 / 가족 구성 / 라이프스타일 추론
- 가전 패턴 → 가구 구성원 수 추론
- 외출 패턴 → 보안 위험

운영 정책 — **전기 사용량은 PII 와 같은 등급으로** (별도 동의, 컬럼 단위 마스킹, 감사).

### 1.2 분산에너지 활성화 특별법 (2024 시행)

- 시민 분산자원 (태양광·ESS·EV) 의 시장 참여 합법화
- **P2P 거래는 특별법 시범사업 안에서만** — 일반 사업은 전기사업법 위반 위험
- 동네에너지의 P2P 거래는 시범사업 등록 후 운영 (확인 필요)

### 1.3 ISMS / ISMS-P

- 매출 100억 이하 — ISMS 의무 대상 아님 (확인 필요)
- 단 **공공 위탁 계약 자체가 ISMS-P 수준 보안 요구** — 사실상 의무

## 2. 공공 위탁 책임

### 2.1 공공 위탁자 책임의 무게

| 측면 | 1권 (PG 위탁) | 2권 (공공 위탁) |
|------|--------------|----------------|
| 사고 영향 | 매출 감소 | **사업 중단** |
| 점검 주기 | 연 1회 | 분기 1회 + 수시 |
| 보고 의무 | 사고 발생 시 | **분기 정기 보고 + 사고 시 즉시** |
| 데이터 외부 이전 | 가능 (해외 데이터 동의 후) | **국내 한정 + 공공 사전 승인** |
| 종료 시 | 사업 종료 | **공공 위탁 회수 + 평판 손상** |

### 2.2 보호 의무 — 1권 외 추가

- 시민 데이터 한국 리전 강제 ([케이스 8](../case-study/README.md#8-인프라--클라우드-정책))
- 정기 보안 감사 보고서 공공 제출
- 위탁 종료 시 데이터 인계 + 안전한 파기

## 3. 개인정보 — 전기 사용량 처리

### 3.1 수집 동의

- **기본 동의** (가입 시): 가구 식별·전력 사용량 수집·기본 서비스 제공
- **별도 동의** (옵트인):
  - DR 참여 → 한전 / KPX 와 데이터 공유
  - P2P 거래 → 이웃 가구와 거래량 공유 (개인 식별 X)
  - 취약계층 보호 → 사회복지사·복지부 데이터 공유
  - 통계 / 공공 데이터허브 공유 → 동·면 단위 집계 익명화

### 3.2 마스킹 / 가명

- 사내 분석은 **가명 가구 ID** (해시) 만 사용
- 공공 송신은 **익명** (동·면 단위 집계, 가구 식별 불가)
- LLM 컨텍스트는 가구 ID 제거 + 패턴만

### 3.3 보존

- 시민 전력 사용량: 5년 (개보법 시행령) — 1시간 집계 기준
- 정산 기록: 영구 (세무·정산 분쟁 대비)
- 웨어러블 (취약계층 안전): 6개월 (의료 연계 분쟁 시 연장)

## 4. 인증 / 본인인증

- 자체 회원: bcrypt cost ≥ 12 / Argon2id
- 본인인증: PASS 우선 (시니어 친화) + NICE 보조
- 간편로그인: 카카오 / 네이버
- MFA: 사회복지사·진단사·관리자만 TOTP — 일반 시민은 PASS 단일

## 5. 결제 / 정산

### 5.1 정산 흐름의 보안

- DR 보상 → 세종페이 (지역화폐) 환급 — 시민 ↔ 한전 (우리는 중개)
- P2P 거래 → 시민 ↔ 시민 (우리는 정산)
- 매칭 시공사 정산 → 토스페이먼츠 + 세금계산서

### 5.2 위탁자 책임 — PG + 지역화폐

- 토스페이먼츠 (PG) — 1권과 같은 책임
- 세종페이 (지역화폐) — 별도 협력 + 분기 reconciliation

## 6. IoT 보안 — 1권에 없던 영역

### 6.1 게이트웨이 / 미터 보안

- 가구 게이트웨이 ↔ 클라우드 — 모든 통신 mTLS
- 게이트웨이 고유 인증서 + 자동 갱신
- 펌웨어 OTA 업데이트 — 서명 검증

### 6.2 변조 방지

- 스마트미터 데이터 변조 시도 (P2P 거래 사기 등) — 한전 AMI 데이터와 일 단위 reconciliation
- 의심 패턴 (급격한 증감 / 0 으로 떨어짐) → 자동 알람

## 7. 어드민 / 권한 — 사회복지사 특별 케이스

```
관리자 (소수)
운영자 (시민 응대 / 매칭 / 정산)
↓
시민 (자기 데이터)
진단사 / 시공사 (자기 매칭)
사회복지사 (담당 시민 안전 데이터 + 별도 동의 기록)
```

사회복지사 접근은 **시민 별도 동의 + 접근 시마다 기록 + 동의 철회 시 즉시 차단**.

## 9. 사내 보안 운영 — 25명 조직

| 영역 | 1권 (220명) | 2권 (25명) |
|------|-------------|----------|
| 보안 전담 | 6명 (보안 본부) | 1명 + 외부 자문 |
| 시크릿 관리 | Vault / AWS Secrets | NCP Secret Manager |
| ISMS-P 단골 8가지 | 모두 자체 | 일부 외부 자문 (위탁자 관리·PIA·DR drill) |
| 외부 모의해킹 | 분기 1회 | 반기 1회 (예산 한정) |

## 10. 케이스 — 동네에너지 보안 우선순위

1. **취약계층 데이터 별도 동의 + 접근 기록**
2. **시민 전력 사용량 = 준 민감정보 취급** (마스킹·감사·5년 보존)
3. **공공 위탁 분기 보고서 자동 생성**
4. **P2P 거래 시범사업 등록 + 정합 reconciliation 일 단위**
5. **IoT 게이트웨이 mTLS + OTA 서명**

## 정리 — 체크리스트

- [ ] 전기 사용량을 PII 등급으로 처리하는가
- [ ] DR / P2P / 사회복지 영역별 별도 동의 화면이 있는가
- [ ] 공공 위탁 계약서 보안 조항이 운영 룰에 반영되었는가
- [ ] IoT 게이트웨이 mTLS / OTA 서명이 적용되는가
- [ ] 사회복지사 접근에 시민 별도 동의 + 기록이 강제되는가
- [ ] 분기 보고서가 자동 생성되는가
