# 대한민국 서비스 아키텍트 입문서 — 베타 리뷰 안내

> 베타 리더님께. 시간 내 주셔서 감사합니다.
> 이 문서를 끝까지 읽으신 뒤 리뷰를 시작해주세요. 약 5분이면 충분합니다.

## 1. 책의 의도

대한민국 시장에서 서비스를 처음부터 끝까지 설계할 수 있는 **아키텍트를 양성하는 입문서**.

8개 영역 (아키텍처 · 클라우드 · 백엔드 · 프론트 · 데이터·AI · 보안 · 운영·조직 · 종합) 을 한 가상의 서비스 — **원픽 (월 1,000만 MAU 종합 커머스)** — 위에서 다룹니다.

집필 원칙 ([`CLAUDE.md`](../CLAUDE.md)):

- 한국어 1차 + 영어 병기
- 트레이드오프 중심 ("정답 없음, 선택지와 결과")
- 케이스 단일 출처 (모든 사례는 case-study 에서 인용)
- 다이어그램 / ADR 중심

## 2. 무엇을 검토해 주셨으면 하는가

다음 4가지 시선으로 봐주시면 가장 도움됩니다.

### A. 사실 정확성

- **법규 / 인증 인용** — 시점 / 조문 / "확인 필요" 표시가 맞는지
- **수치 / 통계** — 출처 없이 단정된 부분이 없는지
- **국내 환경** (NCP · KT · NHN · PG · 간편로그인) — 실제 운영과 어긋난 지점

### B. 트레이드오프의 균형

- **AWS-only** 등 단정적 권고가 있는지
- **MSA / 모놀리스 / Native vs RN** 같은 결정에서 한쪽으로 기울었는지
- 자신의 환경 (다른 도메인 / 다른 규모) 과 맞춰봤을 때 적용 가능한지

### C. 케이스 일관성

- 챕터마다 "원픽" 의 모습이 다르지 않은지
- 결정 / 수치 / 도구 선택이 케이스 스터디([`manuscript/case-study/README.md`](../manuscript/case-study/README.md)) 와 어긋나지 않는지

### D. 독자 입장

- 1차 독자 (시니어 백엔드/프론트 → 아키텍트 전환) 에게 적정한 깊이인지
- 너무 추상적이거나 너무 세부적인 절은 어디인지
- 더 보고 싶은 / 빼도 되는 영역

## 3. 무엇을 검토하지 않으셔도 되나

- 맞춤법 / 띄어쓰기 (저자 책임)
- 디자인 / 표지 / 출판 형태 (별도 단계)
- 코드 예제 (`code-samples/` 는 본 회람 범위 밖)
- 빌드 / 출판 도구 (현재 마크다운만)
