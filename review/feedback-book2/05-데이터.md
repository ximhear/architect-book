날짜: 2026-05-18

(2) **한국어 정확도가 GPT-4o / Claude 3.5 대비 항상 우위는 아님** — 코드 / 수치 reasoning / JSON 강제 출력은 GPT-4o-mini 가 우위. "한국어 일상/공공 답변 = HCX, 코드/구조화 출력 = 외부 LLM" 같은 용도별 라우팅 권고 |

| 05장 3 continuous aggregate (line 49~64) | SQL 예시는 깔끔한데, **갱신 실패 / 지연의 운영 영향** 이 빠짐. CA 는 background worker 가 schedule_interval 마다 돌리며 — worker 가 죽거나 VACUUM/lock 경합으로 잡 적체가 발생하면 1~수 시간씩 지연됨. BI/시민 보고서가 "오래된 데이터" 를 보여주는 사고는 흔한 P2 | "CA 갱신 지연 모니터링 — `_timescaledb_internal.bgw_job_stat` 의 `last_run_success`, `next_start` 을 메트릭으로 export. 6시간 지연 시 P2 알람" 한 절. 함정 박스 "CA refresh 가 도메인 transaction 의 long-running query 때문에 큐잉되는 사고" 추가 |

## 2. 트레이드오프 / 균형 (B)

| 위치 | 발견 | 제안 |
|------|------|------|
| 05장 2 TimescaleDB 결정 (line 33~46) | "운영은 TimescaleDB, 분석은 ClickHouse — 두 엔진 조합" 으로 결론. **두 엔진 조합의 운영 비용 (스키마 동기화 / 익스포트 잡 / 두 엔진 모니터링) vs InfluxDB / ClickHouse 단일 사용의 비용 비교가 빠짐**. 25명 조직에서 두 시계열 엔진을 운영하는 부담은 작지 않다. 일 record 임계 (예: 1억/일 미만은 TimescaleDB 단일, 1억+ 부터 ClickHouse 추가) 같은 정량 임계가 본문에 없음 | "TimescaleDB 단일 — 일 5,000만 record 까지 분석 쿼리도 직접. 그 이상에서 ClickHouse 추가 검토" 같은 임계 신호. 또는 "ClickHouse 만 (도메인 DB 분리)" 옵션을 트레이드오프에 추가 — 작은 조직에 단순할 수 있다 |
| 05장 4.1 모델 표 (line 71~76) | "Prophet 운영 부담 — 낮음" 으로 단정. 실제로 Prophet 의 운영 부담은 모델 학습이 아니라 **재학습 cycle + 휴일/특이일 회귀 분석 + 가구 cohort 변경 (이주/입주) 처리** 가 본체. 일 단위 재학습? 주 단위? 임계 신호 (MAPE drift > X) 기반? 가 빠짐 | "Prophet 운영 — 주 단위 재학습 / 휴일 캘린더 (한전 DR 일정 + 한국 공휴일) 주입 / cohort 변경 시 재학습 트리거" 같은 ML lifecycle. drift 모니터링 (MAPE 시계열) 한 줄 |
| 05장 5.2 룰 + XGBoost (line 92~97) | "룰 + XGBoost (선택)" 와 "딥러닝" 만 비교. **현실에서 더 중요한 비교는 "룰 단독 vs 룰 + XGBoost vs 룰 단독 + 인간 리뷰 강화"** — 25명 조직에서 XGBoost 운영 (학습 데이터 라벨링 / 재학습 / drift 모니터링) 비용이 룰만으로 잡을 수 있는 위험 대비 정당한가? | 트레이드오프 표에 "룰 단독 + 인간 리뷰 (사회복지사 0.5 FTE)" 옵션을 추가. 룰만으로 80% 잡고 나머지를 사회복지사 인지에 맡기는 vs ML 로 95% 잡고 5% 를 놓치는 의사결정 |
| 05장 6 LLM 통합 — 6.2/6.3 | "AI Gateway — 외부 LLM (HyperCLOVA X / GPT-4o-mini 등) 라우팅·캐시·비용 추적" 한 줄. **AI Gateway 의 ZRR 보장 / 라우팅 정책에서 PII 가 흘러가는 경로의 격리** 가 빠짐. HCX 만 ZRR 인데 라우팅이 GPT-4o 로 fallback 하면 가구 데이터가 외부로 누출됨 | "PII 경로는 단일 모델 (HCX-ZRR) 고정 / 폴백 없음 / 비 PII 경로만 라우팅" 같은 분리 정책 한 절. 또는 함정 박스 "AI Gateway 의 fallback 이 ZRR 우회 사고를 만든다" |
| 05장 7 공공 데이터허브 양방향 (line 126~142) | "송신 / 수신" 두 절로 깔끔하지만, **양방향 정합 (우리가 송신한 통계와 세종시가 받은 통계의 차이 발생 시 누가 reconcile 하는가)** 이 빠짐. 분기 보고 시점에 발견되면 이미 시민 신뢰 사고 단계. 일 단위 reconciliation 자동화가 빠짐 | "송신 정합 — 일 단위 reconciliation 잡 (우리 송신 측 카운트 vs 세종시 수신 측 카운트 차이 > 0.1% 알람) + 분기 외부 감사" 한 절. 8.1 의 "양방향" 표기와 함께 표 |
| 05장 5.1 입력 신호 윤리 표 (line 85~91) | "별도 동의" 가 반복되는데, **동의 철회 시 모델 재학습 / 학습 데이터 삭제 (GDPR 의 right to be forgotten 한국판) 가 누락**. 운영에서 가장 비싼 부분 중 하나 | "동의 철회 시 — 학습 데이터에서 즉시 제거 + 다음 재학습 cycle 까지의 모델은 영향 받지 않음을 시민에 고지" 한 줄. 또는 함정 박스 "ML 모델은 학습 시점 동의 데이터를 머금는다 — 철회 후에도 추론에 잔존" |

## 5. 잘 된 점 (3개 이내)

1. **케이스 11.2.2 / 11.4 의 단일 출처가 시계열 영역에서 작동.** TimescaleDB + ClickHouse 의 두 엔진 분리, raw / 1시간 / 1일 의 3층 다운샘플링, Prophet / XGBoost / HCX 라는 가벼움 우선의 선택 — 25명 조직의 무게에 맞춰 의식적으로 작게 잡은 결정 골격이 1권의 "거대 스택" 과 명확히 다르게 살아있다.
2. **5.1 입력 신호의 윤리 표 + 5.2 임계 분류 + 인간 리뷰 = 3단 안전 장치.** 취약계층 식별 모델을 "ML 자동 알람" 으로 박지 않고 "ML 후보 → 사회복지사 인간 리뷰 → 알람" 으로 두 단계를 강제한 점이 본 책의 윤리적 정체성을 만든다. 입문 독자가 "ML = 자동" 으로 빠지는 함정을 정확히 차단.
3. **9.2 함정 박스의 4가지 (hypertable 인덱스 / CA 지연 / LLM PII 누출 / 공공 송신 정합)** 가 운영 현실의 핵심을 짚음. 이 4가지는 실제로 데이터팀 3명이 1년차에 모두 한 번씩 밟는 사고. 다만 4D 에서 적었듯 영향/대응 비용까지 한 표로 채우면 박스 자체가 별 한 개짜리 차별화 자산이 된다.

## 6. 종합 한 단락

이 책 2권의 5장은 **시계열 + 공공 데이터 + 윤리적 AI 라는 1권에 없던 결의 결정 골격을 작은 조직 (25명) 의 무게로 깎아낸다는 목표** 에서 큰 그림은 성공이고, 출간 가치가 충분하다고 본다. 다만 시계열 / 공공 데이터 / 취약계층 식별 모델을 실제 운영한 사람의 시각에서는 **5장이 "결정 골격" 까지는 옳지만 "결정 후 1~2년차에 가장 비싸지는 부분" 의 깊이가 1권의 검색 / 추천 챕터에 비해 얕다**. 구체적으로 — **(1) TimescaleDB 의 인스턴스 분리 결정 (도메인 OLTP 와 같은 인스턴스인가, 분리인가)** 이 케이스 / 05장 / 08장에서 다 모호하고, 이게 모호하면 일 2,700만 record 시점에 도메인 트랜잭션이 IoT 쓰기에 잠식되는 사고가 1년차에 터진다. **(2) DR 예측의 단위가 "가구별" 로 잘못 박혀 있다** — Prophet 을 가구별로 돌리면 MAPE 가 무력하다는 운영 현실이 빠져, 입문 독자가 그대로 따라가면 1분기 안에 모델 폐기를 결정하게 된다. **(3) 취약계층 식별의 FP/FN 비용 비대칭과 SHAP 의 사회복지사 노출 UI** 가 빠져, 본 책의 가장 윤리적 정체성이 강한 절이 실무로 가져가기에는 추상적이다. **(4) HyperCLOVA X 의 ZRR 정책 / 가격 / 한국어 정확도가 모델별로 다르다는 사실** 이 빠져, "공공 가점 = HCX 채택" 이라는 단순한 결론이 독자에게 잘못 박힌다. **가장 권하고 싶은 독자는 "공공 사업 / 스마트시티 / 에너지 데이터 플랫폼을 처음 세우는 작은 데이터팀 (DE+ML 2~3명) 의 첫 리드"** — 단, 위 4가지 보강 후. **출간 전 반드시 손봐야 할 한 가지는 "DR 예측 모델의 단위 (가구별 vs 동·면 집계) 와 모델 lifecycle (재학습 cycle / drift / 휴일 캘린더)"** — 본 책이 "시계열 + AI" 라는 차별화를 가장 진하게 내세우는 절인데 현재는 표 한 개로 끝나, "Prophet 채택" 이라는 결론만 남고 운영 현실은 비어있다. 이 한 절을 3배 깊이로 확장하고, 부수적으로 (1) TimescaleDB 인스턴스 분리 결정과 (3) SHAP-사회복지사 UI 두 곳에 각각 한 단락씩 보강하면, 본 책 5장이 1권 5장과 어깨를 나란히 하는 차별화 챕터가 된다.
