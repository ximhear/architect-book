(c) "공공 사업 가점" 표현이 케이스 / 1장 / 8장에 반복되는데 정확한 가점 산정 기준 (조달청 / 행안부 / 산업부의 평가 기준) 없이 단어만 반복되면 과장으로 읽힌다. |

| 06장 6.2 변조 방지 vs case-study 5.2 | "P2P 거래 정합성: 잉여 전력 측정·정산 오차 **0건** 목표" (케이스) vs "한전 AMI 데이터와 일 단위 reconciliation" (챕터) — 두 표현의 정합 수준이 다름. 케이스의 "0건" 은 강해 보이지만 챕터 reconciliation 은 일 단위라 갭 발생 가능. | 케이스 5.2 를 "정산 오차 0.01% 이내 (한전 AMI 와 분기 reconciliation)" 로 정정 — case-study 10.1 "P2P 거래 정합 오차: 한전 측 정산과 0.01% 이내 — 분기 1회 reconciliation" 와 일치시킴 (이미 10.1 에 있음, 5.2 만 정정하면 됨). |

## 5. 잘 된 점 (3개 이내, 형식적 채움 X)

1. **케이스 5.1 의 법규 목록이 8개로 풍부** — 1권보다 에너지 / 공공 / 사회복지 법규를 잘 식별. 단, P1-A 의 「에너지이용합리화법」 오인용 정정 후라면 더 좋다. 다음 챕터에서도 케이스 5.1 의 법규 표를 정본으로 유지할 것.
2. **6장 2 "공공 위탁 책임" 표가 1권 PG 위탁과 5축 비교** — 사고 영향 / 점검 주기 / 보고 의무 / 데이터 외부 이전 / 종료 시. 이 표는 본 책의 정체성을 잘 보여주는 자산. 단, "데이터 외부 이전 — 가능 (해외 데이터 동의 후)" 은 1권에서도 사실 매우 까다로움 (개보법 제28조의8). 5축의 1권 칸도 좀 더 정확히 채울 것.

## 6. 종합 한 단락

이 책의 보안 챕터는 **1권 보안 챕터 대비 분량은 비슷하나 깊이는 영역별로 매우 들쭉날쭉하다**. 가장 큰 문제는 본 책의 정체성인 **(a) 에너지 법규 정확성 (분산에너지 활성화 특별법의 시범사업 / 특화지역 / 소규모전력중개사업의 3축 구분이 없음), (b) IoT 보안 (게이트웨이 인증서 라이프사이클·OTA·공급망 부재), (c) 공공 위탁의 사고 통지 다층 구조 (위탁기관 → 상급기관 → NCSC → 보호위 → KISA → 정보주체) 가 모두 한 줄로 처리** 된 점이다. ISMS-P 심사원이 보면 "이 책은 공공 위탁 한 번도 안 받아본 사람이 썼다" 는 인상을 받는다. **CSAP·KCMVP·PIA 세 단어가 책에 한 번도 안 나온 것은 공공 사업 책에서 치명적**이다 — NCP 단일 선택의 진짜 이유가 CSAP인데 "공공 가점" 으로만 표현되어 있다. 또한 취약계층 영역은 사회복지사 권한 위계만 ASCII 박스로 보여줄 뿐 (Mermaid 도 아님 — ADR-0009 룰 3 위반), 「개인정보 보호법」 제23조 민감정보 / 제37조의2 자동화 결정 거부권 / 「사회보장기본법」 제32조 수급권자 정보 보호와의 연결이 없다 — **이 책의 가장 윤리적으로 중요한 영역이 가장 얕다**. **출간 전 반드시 손봐야 할 한 가지를 꼽는다면**: 6장 6 절 (IoT 보안) 을 현재 6줄에서 챕터 전체의 1/3 분량으로 확장하고 (인증서 라이프사이클 / OTA dual partition·롤백 / 공급망·SBOM / decommission), 동시에 7 절 (사회복지사) 의 ASCII 박스를 Mermaid 시퀀스로 바꾸고 민감정보·프로파일링 거부권을 명시하는 것. 그 다음 우선순위는 **분산에너지 활성화 특별법 / 전기사업법의 P2P 거래 3경로 (특화지역 / 소규모전력중개사업자 / 특별법 직접거래) 트레이드오프** 와 **CSAP·KCMVP·PIA 누락 보완**이다. **출간하기에 부족하지는 않지만, 1차 인쇄 전에 P1-A 6개 + P1-D 4개 + 누락 11개는 반드시 손봐야 한다.** 출간된다면 가장 권하고 싶은 독자는 **"공공 위탁이 처음인 시리즈 A 스타트업의 기술 리드 또는 보안 1인 담당자"** 다 — 다만 정정 없이 그대로 나가면 그 독자가 책을 그대로 따라하다 ISMS-P 점검 / 공공 위탁 보안 점검에서 곤란해질 위험이 있다.
