# 베타 리뷰 — 운영 가이드

> 이 문서는 **저자 / 회람 진행자** 를 위한 운영 가이드다.
> 베타 리더에게 직접 보내는 자료는 [`reviewer-pack.md`](reviewer-pack.md) 에 있다.

## 목적

1차 드래프트(00~08장) 의 구조 · 톤 · 트레이드오프 / 한국 시장 반영도 / 케이스 적용성을 검증하는 외부 시선을 받는다.
출간 직전이 아니라 **구조적 변경이 가능한 시점** 의 회람이다 ([ADR-0002](../adr/0002-샘플-챕터-우선순위.md) 마지막 follow-up).

## 모집 — 베타 리더 풀

목표: **5~10명**. 분야별 분포 권장.

| 분야 | 인원 | 어떤 사람 | 검토 분량 |
|------|------|----------|----------|
| 보안 / 컴플라이언스 | 1 | 금융·핀테크 시니어 / ISMS-P 심사원 경험 | 0·1·6·8장 + 케이스 |
| 인프라 / SRE | 1 | 멀티 클라우드 운영 5년+ | 0·1·2·7·8장 |
| 백엔드 시니어 | 1~2 | Spring + Go 모두 경험 | 0·1·3·5·8장 |
| 프론트 시니어 | 1 | 모바일 + 웹 통합 경험 | 0·1·4·8장 |
| 데이터 / ML | 1 | DW + ML 운영 | 0·1·5·8장 |
| 타깃 독자 (시니어 → 아키텍트 전환자) | 2~3 | 책의 1차 독자상 | 0·1·8장 |

> **공통 — 모두에게**: 0·1·8장 + 케이스 스터디. 나머지는 분야별 선택.

## 일정 (예시)

| 단계 | 시점 |
|------|------|
| D-0 | 회람 발송 (이메일 또는 리포지토리 초대) |
| D+14 | 1차 피드백 마감 |
| D+21 | 분야별 통합 회의 (1시간씩, 비대면 가능) |
| D+30 | 피드백 통합 분류 ([`integration-log.md`](integration-log.md)) 완성 |
| D+45 | 적용 가능 항목 본문 반영 / book-editor 회귀 |

## 피드백 통합 흐름

받은 피드백은 다음 분류로 정리해 [`integration-log.md`](integration-log.md) 에 기록:

| 분류 | 처리 |
|------|------|
| 사실 오류 / P1 | 즉시 수정, ADR 또는 본문 갱신 |
| 트레이드오프 누락 | 박스 추가 / 본문 보강 |
| 형식 / 표기 | book-editor 회귀 후 일괄 |
| 추가 챕터 / 주제 제안 | "보류" 폴더 (다음 판본 후보) |
| 거절 (책 범위 외) | 거절 사유 기록, 베타 리더에게 회신 |

## 산출물

- [`review/feedback/`](feedback/) — 베타 리더별 피드백 마크다운 모음 (받은 그대로)
- [`review/integration-log.md`](integration-log.md) — 적용 / 보류 / 거절 분류 표
- 필요 시 ADR 추가 (`adr/00NN-...md`) — 큰 결정이 회람으로 인해 바뀌면

## 회신 채널 (저자가 결정)

다음 중 택1, 베타 리더에게 명시:

- **이메일**: `reviewer-pack.md` 의 양식 채워 회신 (가장 단순)
- **GitHub PR**: `review/feedback/<리뷰어이름>.md` 파일로 PR (이력 명확)
- **GitHub Issue**: `[베타 피드백]` 라벨로 (스레드 토론 자연스러움)

권장: **GitHub Issue** — 스레드로 후속 질문 가능, 라벨로 분류 자동.

```
피드백 작성: 약 30~60분

회람 안내: review/reviewer-pack.md

```
