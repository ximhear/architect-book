| 05장 2.1 CDC vs 야간 dump (line 99~109) | "둘 다 사용" 으로 끝남. **현실적으로 가장 비싼 부분 — 둘의 데이터가 어긋날 때 (CDC 는 OrderPaid 가 왔는데 야간 dump 는 안 잡힘 등) 누가 어떻게 reconcile 하는가** 가 빠짐. 정산처럼 정확성 100% 가 요구되는 영역에서 CDC + dump 병행은 매주 reconciliation report 가 필요한 노동 | "이중 파이프라인 정합성 검증 — 일 단위 reconciliation 잡 / 차이 임계 알림" 을 한 절로. 또는 함정 박스에 "CDC 와 야간 dump 의 미세한 차이가 분석 KPI 의 신뢰도를 갉아먹는다" 추가 |
| 05장 3.3 Lambda vs Kappa (line 152~174) | Lambda 의 운영 부담이 크다고 짧게 끝남. **정산처럼 정확성 100% 가 요구되는 영역에서는 사실상 Lambda 가 강제** — 그 운영 부담을 어떻게 분담하는지 (배치팀 vs 스트림팀? 또는 한 팀이?) 가 빠짐. Kappa 로 정산을 처리한 사례는 거의 없는데, 본문은 양자 동등하게 보임 | "정산 / 매출 인식 같은 회계 도메인은 Lambda + 야간 배치를 source of truth 로 두고, 스트림은 모니터링/대시보드 용도" 같은 명확한 용도 분리 권고 |
| 05장 4.4 / 8.2 LTR rerank | LTR 의 학습 데이터 (사용자 클릭 로그) 가 어떻게 모이고 어떤 편향 (poison) 을 가지는지가 빠짐. "rerank 모델을 일 단위 재학습" 같은 운영 사이클이 빠지면 첫 모델만 좋고 6개월 후 drift 로 검색 품질이 무너짐 | "클릭 로그 → LTR 학습 셋 → 일/주 단위 재학습 → A/B → 점진 rollout" 의 ML lifecycle 한 절. drift 모니터링 (NDCG, MRR 의 시계열) 도 한 줄 |
| 05장 6 LLM 통합 — 비용 절 (6.4) | "캐시 / 모델 라우팅 / 토큰 제한 / 스트리밍" 4가지로 정리됐는데, **실제 비싸지는 부분 — RAG 의 임베딩 재생성 비용 (스키마 변경 / 청크 정책 변경 시 1.2억 리뷰 전체 재임베딩)** 이 빠짐 | "RAG 의 재임베딩 비용 — 청크 / 임베딩 모델 변경은 신중. 모델 변경 시 비용 시뮬레이션 후 결정" 같은 한 줄. 1.2억 리뷰 임베딩 1회당 비용 추산 (가정값이라도) 한 표 |

## 5. 잘 된 점 (3개 이내)

1. **케이스 11.4 의 단일 출처 구조가 데이터 영역에서 잘 작동.** Lake (S3 + Iceberg) + Warehouse (BigQuery) + Flink + dbt Core 라는 비교적 모던하고 일관된 스택을 한 곳에 박아두고, 챕터에서는 그 결정의 근거와 적용을 다룸. 이 패턴이 데이터 영역처럼 도구 폭발이 심한 곳에서는 특히 유효.
2. **Lambda vs Kappa 를 다이어그램 + 표로 정리한 부분 (3.3)** 이 입문서로서 적절한 깊이. 정산 영역에서 Lambda 가 현실적이라는 한 줄이 들어간 점이 실무 감각이 살아있음.
3. **함정 박스 (8장 끝, "Iceberg 도입 시 dbt 와의 호환성 / Two-tower 라벨 누수 / CDC 부하 / PII 마스킹 미커버 컬럼")** 가 짧지만 실무에서 정확히 발생하는 사고 4가지를 짚음. 이런 박스를 각 절마다 1개씩 더 넣어주면 책의 신뢰도가 크게 오름.

## 6. 종합 한 단락

이 책의 5장은 **데이터 플랫폼의 큰 그림을 입문 독자에게 한 번에 보여준다는 목표** 에서는 성공이고, 이 책이 출간될 만하다는 데 동의한다. 다만 데이터/ML 영역의 1차 독자 — 시니어 백엔드 → 데이터 플랫폼 리드 전환을 노리는 사람 — 가 이 책 한 권으로 데이터 플랫폼을 세우려 들면, **1년 후 가장 비싸질 부분 (사용자 사전 갱신 / Feature Store 의 학습-서빙 skew / dbt 모델 200개 시점의 자체 Airflow 스케줄러 / RAG 재임베딩 비용 / CDC + 야간 dump 의 reconciliation 노동)** 에서 모두 매주 시간을 갉아먹게 될 것이다. 이 책의 강점인 트레이드오프 골격은 살리되, 5장은 "도구 비교" 보다 "도구를 세운 후 1~3년차에 무엇이 비싸지는가" 의 절을 한 군데 추가해야 한다 — 본 책의 가장 중요한 가치 ("나중에 비싸지는 결정을 지금 싸게") 가 다른 챕터에서는 잘 살아있는데 데이터 챕터에서만 약하다. **가장 권하고 싶은 독자는 "도메인팀 백엔드 시니어 / 작은 데이터팀 (DE 2~3명) 의 첫 데이터 플랫폼 리드"** — 단, 위 운영 함정 절이 보강된 후. **출간 전 반드시 손봐야 할 한 가지는 "한국어 검색 (4.2)" 의 깊이** — 본 책의 차별화 (한국 시장 한정) 가 가장 진하게 살아야 할 절인데 현재는 4가지 항목 한 문단씩에 그쳐, "Nori + 사용자 사전" 이라는 케이스 결정의 운영 현실을 거의 안 보여준다. 이 한 절만 2~3배 깊이로 늘려도 책 전체의 한국 시장 정체성이 단단해진다.
