# 케이스 스터디 — 원픽(OnePick)

> 이 책 전체를 관통하는 가상의 대한민국 종합 커머스 서비스.
> 모든 장의 예제·다이어그램·트레이드오프 논의는 이 서비스를 기준으로 한다.
>
> 실존하는 어떤 회사와도 무관하다. 다만 국내 시장의 평균적인 모습을 의도적으로 합성했다.
>
> 본 문서는 [ADR-0008](../../adr/0008-케이스-단일-출처-원칙.md) 에 따라 원픽에 대한 **단일 출처(Single Source of Truth)** 다.
> 챕터에서 새로운 원픽 사실이 필요하면 먼저 본 문서를 갱신한 뒤 챕터에서 인용한다.

## 한 문장 정의

**원픽**은 월 1,000만 MAU 규모의 종합 커머스 플랫폼이다.
직매입(자체 매입 + 자체 풀필먼트) 과 입점(오픈마켓) 을 1:2 비율로 함께 운영하며, 모바일 앱이 트래픽의 80% 를 차지한다.
설립 7년차, 시리즈 D 까지 마친 비상장 스타트업.

## 1. 비즈니스 / 도메인

### 1.1 사업 모델

| 채널 | 비중 (GMV 기준) | 특징 |
|------|----------------|------|
| 직매입 | 30% | 자체 물류센터 2곳 (이천·김해), 마진 평균 22% |
| 입점 (오픈마켓) | 60% | 셀러 약 8만 명, 수수료 평균 12% |
| 라이브커머스 | 10% | 자체 스튜디오 + 외부 셀러 송출, 자체 CDN 거치는 RTMP |

### 1.2 핵심 도메인

```
회원 (Identity)        — 가입·로그인·본인인증·간편로그인
상품 (Catalog)         — SKU·옵션·카테고리·검색·추천
주문 (Order)           — 장바구니·주문·결제·취소·교환·환불
결제 (Payment)         — PG 연동·간편결제·정산
배송 (Fulfillment)     — 풀필먼트(직매입) + 셀러 직배송(입점)
정산 (Settlement)      — 셀러 정산 (월 2회), 환급/세금계산서
프로모션 (Promotion)   — 쿠폰·적립금·할인·이벤트·라이브
리뷰 (Review)          — 상품 후기·평점·이미지/영상
검색 (Search)          — 키워드·필터·자동완성·연관검색
추천 (Recommendation)  — 개인화·연관상품·재구매 예측
정책 운영 (Trust)      — 어뷰징·가품·CS·분쟁
```

### 1.3 비즈니스 KPI

- **GMV**: 연 1.2조 원 (월 1,000억 원 평균, 11월/명절 1.8배)
- **매출**: 약 1,800억 원 (수수료 + 마진)
- **주문 수**: 일평균 8만 건 (피크일 30만 건)
- **객단가**: 약 4만 원
- **반품률**: 직매입 8%, 패션 카테고리 25%
- **재구매율**: 6개월 기준 45%

### 2.3 매출·비용 가이드라인

- IT 인프라 비용: 매출의 10~14% (연 180~250억). 멀티 클라우드 + AI / 라이브 활용 가정으로 한국 커머스 평균(약 6~8%) 대비 다소 높음
- 단일 클라우드 종속 비용 한도: 전체 인프라의 80% 이하 (멀티클라우드 전제)
- AI / 추천 GPU 비용: IT 비용의 15% 이내

## 5. 제약 / 컴플라이언스

### 5.1 법규 (대한민국)

> ⚠️ 아래는 책 집필 시점 기준의 일반론이다. 실제 적용 시 최신 조문과 가이드라인을 반드시 확인.

- **개인정보보호법**: 회원·주문·결제 정보의 분리 저장, 접근 통제, 암호화
- **정보통신망법**: 개인정보 처리 동의·고지, 위치정보
- **전자상거래법**: 주문/결제 기록 5년 보존, 청약철회·환불 기한
- **여신전문금융업법 / 전자금융거래법**: 결제·간편결제 처리 시 PG 위탁 vs 자체 처리 구분
- **표시광고법**: 가격 표시, 할인 비교, 부당광고 금지
- **ISMS-P**: 정보통신서비스 매출 100억 이상이면 의무 대상

### 5.2 비즈니스 제약

- **결제 실패율**: 0.5% 이하 (주요 KPI)
- **PG 다중화**: 단일 PG 장애가 전체 결제 중단으로 이어지지 않을 것 (PG 3사 이상)
- **셀러 정산 지연 무관용**: 약정일 미준수 시 법적/평판 리스크 큼
- **재고 정합성**: 오버셀(없는데 팔리는 것) 0건 목표 — 이벤트 시 가장 큰 골치
- **CS 응답 SLA**: 영업시간 내 4시간, 야간/휴일 24시간

### 5.3 기술 제약

- **국내 응답 지연**: p95 < 300ms (서울/수도권 기준)
- **모바일 데이터 절약**: 첫 화면 < 200KB (저사양 / 비도시 사용자 고려)
- **앱 콜드 스타트**: < 2.5s (Android 저사양 기준)
- **검색 첫 결과**: < 400ms (자동완성은 < 100ms)

## 8. 인프라 / 클라우드 정책

> 이 절은 **정책 수준의 제약** 만 명시한다.
> 구체 채택(제품·버전·토폴로지)은 [11. 기술 스택 상세](#11-기술-스택-상세-가정) 에 둔다.

- **멀티클라우드 전제**: 주 클라우드 + 보조 클라우드 (재해복구·일부 워크로드)
- **국내 클라우드 사용**: 개인정보 핵심 데이터 일부는 국내 클라우드(NCP/KT/NHN) 에 보관 가능성 검토
- **하이브리드 옵션 열어둠**: 라이브 스트리밍 인코딩은 자체 IDC 가능성
- **단일 리전 의존 금지**: AZ 2개 이상, 핵심 도메인은 멀티 AZ 액티브-액티브
- **데이터 주권**: 회원 / 결제 정보는 한국 리전에만 보관

## 9. 시점

이 케이스가 가정하는 시점: **2026년 상반기**.
이 시점의 기술 트렌드 (Cloud Native 보편화, Fluid Compute, Cache Components, AI Gateway, MCP 등) 를 자연스럽게 활용한다.
다만 챕터에서 특정 버전·제품을 인용할 때는 본문에서 별도 명시한다.

## 10. 시작 시점에서 풀어야 할 핵심 문제

본 케이스가 책의 각 장에서 자연스러운 사례가 되도록, 의도적으로 다음과 같은 "현재 진행형 문제" 를 갖고 있다고 가정한다.

| 영역 | 현재 문제 | 다루는 장 |
|------|----------|----------|
| 아키텍처 | 5년차에 만든 모놀리스가 한계 — 모듈러 모놀리스 vs MSA 전환 의사결정 필요 | 1장 |
| 인프라 | 단일 클라우드 종속 — 비용 협상력 / 리스크 분산 필요 | 2장 |
| 백엔드 | 주문/결제의 트랜잭션 일관성 — 분산 트랜잭션·Saga 검토 | 3장 |
| 데이터 | 분석/추천의 실시간성 한계 — 배치 → 스트림 전환 | 5장 |
| 프론트 | 앱·웹·라이브의 중복 구현 — 디자인 시스템·BFF 정리 | 4장 |
| 보안 | 입점 셀러 어드민의 권한 모델 — 정책 일관성·감사 로그 | 6장 |
| 운영 | 도메인팀 자율 vs 플랫폼 가드레일의 균형 | 7장 |

### 10.1 구체 신호 (수치 기준)

위 표의 추상 문제들이 다음과 같은 구체 신호로 나타나고 있다고 가정한다.
이 수치들은 7개 챕터 전체에서 동일하게 인용되며, 새로운 사실이 필요할 때는 본 절을 먼저 갱신한다 ([ADR-0008](../../adr/0008-케이스-단일-출처-원칙.md)).

- **조직**: 5년간 엔지니어 60명 → 220명 (약 3.7배 증가)
- **배포 빈도**: 일 평균 1회. 도메인팀 간 머지/배포 충돌 주 평균 5건
- **모놀리스 빌드/배포**: 풀빌드 12분, 배포 사이클 25분 (긴급 핫픽스 부담)
- **DB 부하 분포**: 메인 Aurora MySQL 의 CPU 중 검색·추천 관련 쿼리가 평균 50% 차지
- **결제 도메인 락**: 결제 트랜잭션 락이 월 1~2회 주문 처리량을 5분 이상 정체시킴
- **장애 회복(MTTR)**: P1 인시던트 평균 45분 (목표 30분 미달)
- **에러 버짓**: 결제 SLO(99.99%) 의 분기 평균 70% 소진 — 빠듯함
- **명절/이벤트 트래픽**: 평소 대비 정확히 8배(피크 8,000 RPS) 가 작년 추석에 관측됨
- **서비스 개수**: 모놀리스 1개 + 추출 서비스(검색·추천·라이브) — 총 약 80개의 운영 단위(컨테이너 워크로드 기준)

> 위 수치는 모두 가공이지만, 책 전체에 걸쳐 일관되게 사용된다. 챕터에서 인용 시 본 절(10.1)을 출처로 표기하면 된다.

## 11. 기술 스택 상세 (가정)

#### 11.2.5 인증 / 토큰

- **자체 회원**: bcrypt cost ≥ 12 또는 Argon2id
- **간편로그인**: 카카오 / 네이버 / 구글 / 애플 — OAuth2 / OIDC
- **본인인증**: PASS / NICE / KCB — 다중화
- **모바일 토큰**: Access (15분) + Refresh (30일, rotate + reuse detection — 탈취 회복)
- **웹 세션**: HttpOnly Cookie + SameSite=Lax + CSRF 토큰
- **MFA**: 셀러 어드민·사내 어드민 TOTP 강제

## 13. 이 케이스가 의도적으로 다루지 않는 것

책의 폭과 깊이의 트레이드오프를 위해 다음은 본 케이스 범위 밖으로 둔다.

- **B2B / 도매**: 본 케이스는 B2C 종합몰
- **글로벌 다국가 운영**: 한국 시장 단일
- **자체 PG 운영**: 외부 PG 위탁 전제 (전금법 직접 적용 회피)
- **암호자산 / NFT 결제**
- **자체 물류 시스템 (WMS) 의 깊이 있는 설계**: 풀필먼트는 외부 SaaS 가정
- **광고 플랫폼**: 트래픽 일부는 광고로 들어오지만, 자체 DSP/SSP 는 다루지 않음

> 위 항목은 책의 다른 시점·다른 케이스로 다룰 가치가 있는 주제다. 단, 본 책에서는 명확히 제외.
